# 윈도우 데스크톱 육성 게임 — 설계 문서

작성일: 2026-08-03

## 1. 개요

웹브라우저에서 동작하는 육성 게임. 화면 전체가 가짜 윈도우 OS로 구성된다. 플레이어는 잠금화면에서 이름을 입력해 로그인하고, 바탕화면에서 인터넷·폴더·exe를 사용하며 자신의 캐릭터를 육성한다.

**핵심 컨셉:** UI가 곧 게임플레이다. 윈도우를 실제로 쓰는 것처럼 브라우저를 열어 사이트를 둘러보고, 폴더를 탐색하고, 프로그램을 실행하는 행위가 게임 진행이 된다.

**기술 스택:** Vite + React + TypeScript, Zustand(상태 관리), Vitest(테스트)

## 2. 게임 규칙

### 2.1 기본 구조

| 항목 | 내용 |
|---|---|
| 캐릭터 | 잠금화면에서 입력한 user명 = 플레이어 자신 |
| 시간 단위 | 턴제. 1일 = 오전/오후 2슬롯. 밤은 자동 취침(체력 회복 + 일일 정산) |
| 게임 길이 | **날짜 제한 없음.** 작업표시줄 시계는 계속 흐르며 날짜를 표시한다 |
| 종료 조건 | 엔딩 도달(선택형) 또는 파산·번아웃(강제) |

### 2.2 스탯

| 스탯 | 성격 | 역할 |
|---|---|---|
| 💪 체력 | 소모 자원 + 성장 스탯 | 활동 시 소모, 취침으로 회복. 부족하면 활동 실행 불가 |
| 🧠 지능 | 성장 스탯 | 공부 성과, 고소득 알바 지원 조건 |
| ✨ 매력 | 성장 스탯 | 인간관계, 일부 엔딩·이벤트 조건 |
| 😊 멘탈 | 소모 자원 | 낮으면 모든 활동 효율 급감. 0이면 번아웃 엔딩 |
| 💰 소지금 | 자원 | 매일 생활비로 차감. 0이면 파산 엔딩 |

**체력은 현재값과 최대값을 분리한다.** (`stamina` / `maxStamina`)

- 현재 체력: 활동으로 소모되고 취침으로 회복되는 일일 자원
- 최대 체력: 운동으로 영구히 상승하는 성장 스탯. 철인 엔딩의 판정 대상

이 분리가 없으면 "체력이 소모 자원이면서 동시에 육성 대상"이라는 모순이 발생한다. 운동은 현재 체력을 소모하면서 최대 체력을 올리는 활동이 된다.

### 2.3 행동 비용 원칙

**탐색은 무료, 확정 행동만 1턴을 소모한다.**

- 무료: 창 열기/닫기, 브라우저로 사이트 이동, 목록 비교, 폴더 탐색
- 1턴 소모: "지원하기", "구매하기", exe 실행 등 결과가 발생하는 확정 행동

턴 소모 행동은 시각적으로 명확히 구분하여 실수를 방지한다.

이유: 실제 윈도우에서 브라우저로 사이트를 둘러보는 것은 "행동"이 아니라 "탐색"이다. 그 감각을 유지해야 컨셉이 산다. 또한 탐색에까지 턴을 소모하면 플레이어가 정작 원하는 활동을 못 해보고 압박에 몰린다.

### 2.4 압박 장치

날짜 제한이 없으므로 다음 세 장치가 시간 압박을 대체한다.

**① 생활비 (핵심)**

매일 밤 정산 시 소지금에서 생활비가 차감된다. 소지금이 0 이하가 되면 즉시 파산 엔딩.

**② 물가 상승**

10일 주기 계단식으로 생활비가 인상된다. 인상 며칠 전 포털 뉴스로 예고한다.

```
1~10일차:   30,000원/일   여유. 스탯 투자 가능
11~25일차:  38,000원/일   알바 비중을 늘려야 함
26~45일차:  50,000원/일   알바만 해도 겨우 본전
46일~:      70,000원+/일  버틸 수 없음. 승부를 봐야 함
```

**알바비는 물가보다 느리게 오른다.** (예: 물가 +25%일 때 알바비 +15%)

이 설계가 만드는 효과:
- 후반으로 갈수록 저임금 알바의 실질 효율이 하락 → 서서히 조여옴
- 지능·매력을 키우면 고소득 알바로 전환 가능 → 스탯 투자에 명확한 보상
- 결과적으로 물가 상승이 단순 페널티가 아니라 **성장의 이유**가 된다

**③ 번아웃 누적**

같은 활동을 연속 실행하면 효율이 감소하고 멘탈이 추가 소모된다. 없으면 "최고 효율 활동 하나만 무한 반복"이 최적해가 되어 선택지가 무의미해진다.

### 2.5 엔딩

**엔딩 조건은 비공개.** 도감을 통해 한 번 본 엔딩만 해금된다.

**성취 엔딩** — 조건 도달 시 팝업이 뜨고 선택할 수 있다.

```
┌─ 🏆 엔딩 도달: 중견기업 합격 ──────────┐
│  지능 70을 달성했습니다.               │
│  ✨ 엔딩 도감에 기록되었습니다.         │
│                                        │
│  ...하지만 아직 더 높은 곳이 있을지도?  │
│                                        │
│      [ 엔딩 보기 ]   [ 계속하기 ]      │
└────────────────────────────────────────┘
```

- 어느 쪽을 선택하든 **도감에 즉시 해금**된다. 이미 확보했으므로 안심하고 계속 도전할 수 있다
- 상위 티어 엔딩이 남아있으면 "더 높은 곳이 있을지도?" 문구로 암시한다. 조건은 여전히 숨긴다
- 최상위 엔딩에서는 암시 문구가 나오지 않는다
- "계속하기"는 도박이다. 물가는 계속 오르므로 파산 위험이 커진다

**실패 엔딩** — 선택권 없이 즉시 종료된다.

- 💀 파산: 소지금 0
- 🔥 번아웃: 멘탈 0

성취 엔딩만 미룰 수 있고 실패 엔딩은 강제여야 압박 장치가 의미를 갖는다.

**엔딩 목록 (6종):**

| 엔딩 | 조건 방향 |
|---|---|
| 🏆 대기업 합격 | 지능 高 + 멘탈 유지 |
| 🌟 인플루언서 | 매력 高 |
| 💪 철인 | 체력 高 |
| 💸 현실주의자 | 소지금 高 |
| 🔥 번아웃 | 멘탈 0 (배드엔딩) |
| 😐 평범한 일상 | 두드러진 스탯 없음 (기본 엔딩) |

## 3. 화면 구조

화면은 잠금화면과 바탕화면 두 개뿐이며, 그 위에 모든 것이 창으로 올라간다.

### 3.1 잠금화면

윈도우 로그인 화면 형태. 배경 + 시계 + 아바타 + 이름 입력창.
이름 입력 → 로그인 애니메이션 → 바탕화면 진입.
기존 세이브가 있으면 이름 입력 대신 "이어하기 / 새로 시작"을 표시한다.

### 3.2 바탕화면

```
┌──────────────────────────────────────────────────┐
│ 🌐        📁                    ┌──────────────┐ │
│ 인터넷    내 문서               │ 김철수       │ │
│                                 │ 💪 체력  70  │ │
│ 💼        📚                    │ 🧠 지능  20  │ │
│ 알바.exe  공부.exe              │ ✨ 매력  15  │ │
│                                 │ 😊 멘탈  80  │ │
│ 🏃        🎮                    │ 💰  50,000원 │ │
│ 운동.exe  게임.exe              └──────────────┘ │
│                                                  │
│ 🗑️                                               │
│ 휴지통                                           │
├──────────────────────────────────────────────────┤
│ ⊞  [🌐 인터넷]        3월 5일(수) 오전 ☀️   ⏭️ │
└──────────────────────────────────────────────────┘
```

- **우상단 스탯창:** 항상 표시되는 창. 이동 가능하되 닫히지 않는다
- **작업표시줄:** 시작 버튼 · 열린 창 목록 · 날짜/슬롯 표시 · 턴 넘기기 버튼(아무 활동 없이 다음 슬롯으로)
- **아이콘 3종류:** `.exe`(즉시 활동) / `폴더`(탐색형) / `인터넷`(사이트 컨테이너)

### 3.3 창 시스템 — 기술적 핵심

모든 UI가 하나의 공용 `Window` 컴포넌트 위에 올라간다. 스탯창, 활동창, 브라우저, 결과 팝업, 엔딩 도감 전부 포함된다.

담당 기능: 드래그 이동, z-index 관리, 최소화/닫기, 작업표시줄 연동.

여기에 먼저 투자하면 이후 모든 콘텐츠 추가가 "창 하나 더 만들기"로 끝난다. 반대로 부실하면 창마다 동작이 제각각이 되어 전부 다시 만들어야 한다. **가장 먼저, 가장 튼튼하게 구현한다.**

### 3.4 브라우저 창

인터넷 아이콘을 열면 주소창·즐겨찾기·뒤로/앞으로 버튼이 있는 가짜 브라우저가 뜬다.

**첫 화면은 포털 사이트(NEVER)다.**

```
┌─ 🌐 인터넷 ───────────────────────────────────── ─ □ ✕ ┐
│ ← → ⟳  [ https://www.never.com        ]              │
├───────────────────────────────────────────────────────┤
│                    N E V E R                          │
│              ┌─────────────────────┐                  │
│              │ 검색어를 입력하세요 │ 🔍               │
│              └─────────────────────┘                  │
│                                                       │
│   💼알바몬   🛒쇼핑   💬SNS   📖강의   🏦은행         │
│  ─────────────────────────────────────────────        │
│  📰 뉴스                                              │
│   • 물가 3개월 연속 상승... 생활비 부담 가중          │
│   • 취업 시장 한파, 신입 채용 30% 감소                │
│   • [광고] 지금 가입하면 10만원 즉시 지급!            │
│  ─────────────────────────────────────────────        │
│  🔥 실시간 검색어                                     │
│   1. 단기 고수익 알바    2. 공무원 시험 일정          │
└───────────────────────────────────────────────────────┘
```

**포털 뉴스 영역이 게임의 피드백 창구 역할을 한다.** 별도 알림 시스템 없이 뉴스로 모든 상태 변화를 전달한다.

- 물가 인상 예정 → 뉴스로 예고
- 특정 스탯이 임계치 도달 → 관련 기사 등장 (엔딩 조건 자연스러운 암시)
- 랜덤 이벤트 → 뉴스/광고 형태로 노출, 클릭 시 발동

**검색창은 1차 구현에서 장식으로 둔다.** (클릭 시 "검색 결과가 없습니다") 자유 입력 검색은 대응 키워드를 무한히 만들어야 해 완성도가 떨어진다. 실검·즐겨찾기 클릭으로만 이동한다. 추후 확장 가능.

**사이트 목록:**

| 사이트 | 역할 |
|---|---|
| 💼 알바몬 | 알바 목록 비교 → "지원하기"(턴 소모) |
| 🛒 쇼핑몰 | 아이템 구매 (스탯 부스터, 회복 아이템) |
| 💬 SNS | 인간관계 활동, 랜덤 이벤트 발생원 |
| 📖 강의 사이트 | 유료 고효율 공부 |
| 🏦 은행 | **1차 구현 제외** (후순위) |

사이트를 데이터 파일로 관리하면 사이트 추가만으로 콘텐츠가 늘어난다. 아이콘 개수에 묶이지 않는 것이 이 구조의 장점이다.

**은행/대출은 1차 구현에서 제외한다.** 없어도 게임이 성립하며, 있으면 밸런싱 난이도가 크게 오른다. 추후 후반 역전 수단으로 추가 검토.

## 4. 기술 설계

### 4.1 상태 관리 — Zustand

React Context 대신 Zustand를 사용한다. 창 드래그 시 좌표가 초당 수십 번 갱신되는데, Context는 스탯창까지 전부 리렌더된다. Zustand는 구독한 값만 반응한다. 또한 `persist` 미들웨어로 localStorage 저장이 간결하게 처리된다.

**스토어 3분리** — 성격이 다른 상태가 섞이면 저장 처리가 곤란해진다.

| 스토어 | 담는 것 | 저장 |
|---|---|---|
| `gameStore` | 스탯, 날짜/슬롯, 물가, 번아웃 기록, 인벤토리 | ✅ 세이브 |
| `windowStore` | 열린 창 목록, 좌표, z-index | ❌ 휘발 |
| `metaStore` | 엔딩 도감 해금 현황 | ✅ 영구 (새 게임에도 유지) |

도감이 `metaStore`에 분리되어야 새 게임을 시작해도 해금 기록이 유지된다.

### 4.2 데이터 파일

밸런싱은 반복 작업이므로 모든 수치를 `src/data/`로 분리한다. 컴포넌트에 하드코딩하지 않는다.

```ts
// src/data/activities.ts — 활동 정의
{
  id: 'study_major',
  label: '전공 공부',
  effects: { intelligence: +5, stamina: -10, mental: -3 },
  requires: { stamina: 10 },       // 부족하면 실행 불가
  cost: 0,
}

// src/data/endings.ts — 엔딩 조건 (평가 순서 = 배열 순서, 상위 티어부터)
{
  id: 'bigtech',
  title: '🏆 대기업 합격',
  condition: { intelligence: 90, mental: 40 },
  tier: 3,                          // 상위 티어 존재 여부 판단용
}

// src/data/economy.ts — 물가 곡선
{ day: 1,  living: 30000, wageMultiplier: 1.0  }
{ day: 11, living: 38000, wageMultiplier: 1.15 }
```

`news.ts`, `sites.ts`, `items.ts`도 동일한 방식. **콘텐츠 추가 = 데이터 파일에 항목 하나 추가**가 목표다.

### 4.3 폴더 구조

```
src/
├── components/
│   ├── window/       Window, WindowManager, TitleBar   ← 최우선 구현
│   ├── desktop/      Desktop, DesktopIcon, Taskbar, StatPanel
│   ├── lockscreen/   LockScreen
│   └── apps/         Browser, ExeApp, Folder, EndingModal, Codex
├── data/             activities, endings, economy, news, sites, items
├── store/            gameStore, windowStore, metaStore
├── systems/          turn.ts, ending.ts, economy.ts, burnout.ts  ← 순수 함수
└── types/
```

### 4.4 systems/ — 게임 로직 분리

게임 로직을 React에서 완전히 분리한 순수 함수로 둔다. `resolveTurn(state, activity) → newState` 형태.

이유: UI 없이 테스트 가능하고, 밸런싱 검증이 쉬우며, 무엇보다 규칙이 한 곳에 모인다.

- `turn.ts` — 활동 실행, 슬롯 전환, 일일 정산
- `ending.ts` — 엔딩 조건 판정, 상위 티어 존재 여부
- `economy.ts` — 물가·생활비·알바비 계산
- `burnout.ts` — 연속 활동 누적 및 효율 감소

### 4.5 저장

`zustand/middleware`의 `persist` 사용. 세이브에 `version` 필드를 포함하고 `migrate` 함수로 스키마 변경에 대응한다. 이를 처음부터 넣지 않으면 개발 중 필드 추가 때마다 세이브가 깨져 매번 삭제해야 한다.

### 4.6 테스트

`systems/`의 순수 함수만 Vitest로 테스트한다. 턴 처리·엔딩 판정·물가 계산·번아웃 누적은 버그 시 게임이 망가지는 지점이며 동시에 테스트하기 가장 쉬운 지점이다. UI 컴포넌트 테스트는 비용 대비 효과가 낮아 생략한다.

## 5. 구현 순서

| 단계 | 내용 | 완료 시점의 의미 |
|---|---|---|
| 1 | **창 시스템** (드래그·z-index·작업표시줄) | 이후 모든 UI의 토대 |
| 2 | 잠금화면 → 바탕화면 → 스탯창 | 진입 흐름 완성 |
| 3 | 턴 시스템 + exe 활동 | 게임이 처음으로 "돌아감" |
| 4 | 경제(생활비·물가) + 엔딩 판정 | **한 판 완주 가능** ← 최우선 목표 |
| 5 | 브라우저 + 포털 + 사이트들 | 콘텐츠 확장 |
| 6 | 도감 · 이벤트 · 폴더 | 마무리 |

**4단계까지 도달하면 처음부터 끝까지 플레이 가능한 게임이 된다.** 이 지점을 최대한 빨리 찍는 것이 중요하다.

## 6. 1차 구현 제외 항목

의도적으로 범위에서 제외하며, 게임 성립에 영향이 없음을 확인한 항목들이다.

| 항목 | 제외 이유 |
|---|---|
| 은행/대출 시스템 | 밸런싱 난이도 급상승. 없어도 성립 |
| 브라우저 자유 검색 | 대응 키워드가 무한히 필요해 완성도 저하 |
| UI 컴포넌트 테스트 | 비용 대비 효과 낮음 |
