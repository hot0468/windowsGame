# windowsGame

화면 전체가 가짜 윈도우 OS인 브라우저 육성 게임.
잠금화면에서 이름을 입력해 로그인하면 바탕화면이 곧 게임판이 된다.

## 게임 규칙

- **캐릭터** — 입력한 이름이 곧 플레이어 자신
- **시간** — 턴제. 하루 = 오전/오후 2슬롯. 오후 행동이 하루를 끝내며 취침 정산이 일어난다
- **행동 비용** — 창을 여는 탐색은 무료. 확정 행동(실행하기)만 1턴을 소모한다
- **날짜 제한 없음** — 대신 세 가지가 압박한다
  - 매일 빠져나가는 생활비 (0원이 되면 파산)
  - 10일 주기 물가 인상. 알바비는 그보다 느리게 올라 후반에 실질 수입이 줄어든다
  - 같은 활동을 반복하면 효율이 떨어지는 번아웃 누적
- **엔딩** — 스탯 조건을 채우면 도달. 조건은 비공개이며 도감으로 해금한다.
  성취 엔딩은 [엔딩 보기]/[계속하기]를 고를 수 있고 어느 쪽이든 도감에 남는다.
  파산·번아웃은 선택 없이 즉시 종료된다

## 스탯 16종

| 구분 | 스탯 |
|---|---|
| 자원 | 행동력(`stamina`) · 체력(`maxStamina`) · 멘탈(0~100) · 소지금 |
| 성장 | 지식 · 매력 · 감수성 · 평판 · 도덕 · 창의력 · 친화력 · 어휘력 · 운동 · 게임 · 예의범절 · 그림 |

상한은 스탯마다 다르다 — 평판·도덕·예의범절만 100이고 나머지는 999다(`growthCap`).
등급은 절대값이 아니라 **상한 대비 비율**로 매긴다(F·C·B·A·S·SS).

## 실행

```bash
npm ci          # 첫 설치
npm run dev     # 개발 서버
npm run build   # 아이콘 서브셋 + 타입 체크 + 프로덕션 빌드
npm test        # 게임 로직 테스트 (691개)
```

## 기술 스택

React 19 · Vite 8 · TypeScript 7 · Zustand 5 · Vitest 4 · Iconify(오프라인 번들)

## 구조

```
src/
├── types/       도메인 타입
├── data/        모든 게임 수치 (활동·물가·엔딩·아이콘)
├── systems/     게임 규칙 (순수 함수, React 비의존)
├── store/       gameStore(세이브) · metaStore(도감) · windowStore(창)
├── icons/       Iconify 서브셋 번들
└── components/  window · desktop · lockscreen · apps
```

**설계 원칙 두 가지**

1. 게임 수치는 전부 `src/data/`에 있다. 밸런싱은 반복 작업이라 코드를 뒤지지 않아도 되게 했다
2. 게임 규칙은 `src/systems/`의 순수 함수다. UI 없이 테스트할 수 있고, `balance.verify.test.ts`가
   실제 시뮬레이션으로 "게임이 완주 가능하고 언젠가 반드시 끝난다"를 지킨다

## 구현 상태

**동작함**

- 셸 — 잠금화면, 격자에 끌어다 놓는 바탕화면 아이콘, 창 시스템(최소화·최대화·복원),
  작업 표시줄, 스탯창·날짜칸, **폭 720px 이하면 가짜 스마트폰 UI로 전환**
- 진행 — 활동 **32종**, 턴·취침 정산, 생활비·물가·번아웃, 스케줄러 예약, 자동 진행,
  엔딩 **11종** 판정(성취 4 · 직업 5 · 실패 2)
- 앱 — 가짜 브라우저(**사이트 15종**), 메신저 2종, 아웃룩, 일정, 파일 탐색기,
  증기(가짜 스팀), 솔리테어, 세이브·작업 관리자·명령 프롬프트
- 경제 — 알바 4종과 정규직 고용(지원→서류→면접→출근·급여), 은행 예금·대출, 이사, 복권,
  쇼핑 3곳(생활용품·전자기기·의류)과 다음 날 배송, 강의·자격증

**미구현** — 평판 시스템(트위터 화면은 있으나 게시가 팔로워를 바꾸지 않는다), 엔딩 도감 UI,
랜덤 이벤트(정의는 `data/events.ts`에 있고 발생 지점만 없다), 휴지통,
사이트 내부 모바일 반응형, 잠금화면 모바일 대응
