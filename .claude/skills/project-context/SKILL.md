# 프로젝트 컨텍스트 (단일 진실 공급원)

이 문서가 코드베이스 탐색을 대체한다. **여기 없는 정보는 아래 참조 파일에서 찾고, 거기에도 없을 때만 파일을 직접 읽어라.**

**갱신 의무:** 설계 결정 변경·새 파일·새 패턴 발생 시 같은 커밋에서 이 문서 또는 해당 참조 파일을 갱신한다.
**작성 규칙:** **규칙만 적는다.** 어떻게 알아냈는지·무엇을 실측했는지·어떤 대안을 기각했는지는 적지 않는다(단, "되살리지 말 것"은 규칙이므로 남긴다). 사연의 정본은 **그 결정이 사는 소스 파일의 주석 하나**다 — CLAUDE.md·HISTORY.md·커밋 메시지에 다시 풀어 쓰지 않는다.
**상한: 이 파일 120줄.** 넘기면 새 줄을 더하지 말고 **먼저 같은 분량을 참조 파일로 내리거나 지운다.** 이 파일은 모든 작업이 통째로 읽으므로 길이가 곧 비용이다(493줄 → 250줄 → 지금. 원칙만으로는 다시 불어난 전례가 두 번 있어 숫자로 못 박는다).

## 게임 컨셉
- 웹브라우저용 육성 게임. UI 전체가 가짜 윈도우 OS다: 잠금화면 → user명 입력 → 바탕화면(게임 메인)
- 입력한 user명 = 플레이어 캐릭터 이름. "나 자신"을 육성(프린세스 메이커 스타일). 우상단에 스탯창 상시 표시

## 디자인 토큰 (상세는 `references/shell.md`)
- ⚠️ **CSS는 정의되지 않은 var를 만나면 그 선언 전체를 무효로 만든다** — 없는 토큰을 쓰면 빌드도 테스트도 통과하고 **화면에서만** 조용히 깨진다. 이 리포에서 이미 세 번 터졌다(`--sp-7`·`--os-line`·`--os-hover`는 **없는 토큰**이다)
- **단일 출처는 `src/index.css`의 `:root`**: 간격 `--sp-1..8`(`--sp-7` 없음), 타입 `--fs-xs..3xl`, 모서리 `--r-sm..xl`, 고도 `--el-1/2/3`(3단만), 색 `--os-*`(OS 크롬)·`--hud-*`(HUD 내부)·`--nv-*`(포털)·`--mo-*`(모바일 셸), 폰트 `--font-base`/`--font-point`/`--font-date`. **컴포넌트 CSS에 생 hex나 임의 px을 새로 적지 않는다**
- ⚠️ **시각 언어를 섞지 않는 것**이 "게임이 OS 위에 얹혀 있다"는 인상의 근거다. **사이트와 사내 프로그램은 예외**로 자기 팔레트를 자기 CSS 파일 안에 가둔다(`--tc-*`·`--wr-*`·`--cc-*` 등). ⚠️ **콜센터(`--cc-*`)에는 브랜드 색이 없다** — 뉴트럴 그래파이트 크롬 + 상태 3색(진행/완료/오답)뿐이고, 그 무채색이 "사내 업무 프로그램"이라는 정체성이다. 장식용 유채색을 넣지 말 것
- ⚠️ **반투명 표면 위 글자색은 토큰이 아니라 합성 결과가 정한다. 눈이나 계산이 아니라 픽셀로 판정한다**(아래 검증 도구)
- ⚠️ 포인트/날짜 폰트는 **게임이 자기 목소리를 내는 자리에만**(`.cal-date`·`.hud-head-title`·`.ending-title`). OS 크롬에는 절대 안 쓴다. 적용 자리는 반드시 `font-weight: 400`

## 아이콘 (상세는 `references/icons.md`)
- ⚠️ **UI에 이모지를 쓰지 않는다.** 이모지 세트는 제거됐고 **다시 들이지 말 것**
- 오프라인 세트 4종: `fluent-color`(다색 — 앱·사이트·활동·엔딩), `mdi`(단색 — HUD·메신저), `mdi-light`(셸 크롬), `devicon`(프로그램 로고). **CDN 금지**. 렌더는 `src/icons/AppIcon.tsx`만 쓴다
- ⚠️ **이름이 존재하지 않으면 `npm run icons`가 빌드를 실패시킨다.** 이름을 지어내지 말고 해당 세트의 `icons.json`에서 확인하라(예: `fluent-color`에는 call/phone 계열 다색 글리프가 **없다**)
- **다색 아이콘에 CSS `color`를 입히지 않는다**(원래 색을 망친다). 색을 입혀야 하면 단색 세트를 쓴다

## 기술 스택
- React 19.2 / Vite 8.2 / TypeScript 7.0 / Zustand 5.0 / Vitest 4.1 / @iconify/react 6. 환경: Windows 11, Node v24.18.0
- 명령: `npm run dev` · `npm run build`(icons && tsc -b && vite build) · `npm test`(vitest run) · `npm run icons` · `node scripts/measure.mjs`(CDP 실측)
- ⚠️ TS7의 `noUncheckedSideEffectImports` 때문에 CSS import에 `src/vite-env.d.ts` 필수

## 파일 맵 (전체는 `references/filemap.md`)
- 진입 `index.html` → `src/main.tsx` → `src/App.tsx` · 도메인 타입 전부는 `src/types/game.ts`
- `src/data/` **게임 수치 전부**(활동·공고·상품·엔딩·레이어·달력·물가…) — 컴포넌트에 수치를 적지 않는다
- `src/systems/` **순수 로직**(턴·경제·번아웃·은행·고용·랭크…) — React import 금지, mutation 금지, `Math.random` 금지. 각각 `.test.ts` 동반 + `balance.verify.test.ts`
- `src/store/` Zustand(gameStore·windowStore·metaStore·browserStore·toastStore·shellStore·desktopIconStore·shortcutStore·desktopPanelStore)
- `src/components/` `window/`(Window·WindowManager·appForWindow — **kind 분기 단일 출처**) · `desktop/` · `mobile/` · `lockscreen/` · `apps/` · `apps/sites/`
- `src/icons/generated.ts`는 **자동 생성이고 수정 금지, 커밋 대상**

## 코딩 컨벤션
- 모든 게임 수치는 `src/data/`로 분리. 주석·UI 텍스트는 한국어. `src/systems/`는 React import 금지, 상태 mutation 금지 — 새 객체를 반환한다
- ⚠️ **스탯을 추가하면 `Stats`·`GROWTH_STAT_KEYS`·`STAT_NAMES`·`STAT_META`·`INITIAL_STATS` 다섯 곳을 함께 고친다**(넷은 `Record<keyof Stats, …>`라 빠뜨리면 빌드가 깨진다) + 그 스탯을 올리는 활동을 만든다(`activities.test.ts`가 지킨다). 스탯 한국어 라벨은 `STAT_NAMES`만 참조한다
- 창 UI는 공용 `Window` 위에 구현한다(**OS 창으로 읽혀야 하는 것 전부**). **예외는 HUD 패널 하나뿐이며 `HudPanel`을 쓴다.** `onClose`를 안 넘기면 닫기 버튼이 사라진다(상시 표시 창용)
- ⚠️ **죽은 컨트롤을 만들지 않는다.** 갈 데 없는 링크·눌러도 아무 일 없는 버튼은 표시 전용(`aria-hidden`)으로 두거나 아예 뺀다
- ⚠️ **관계는 한 방향으로만 적고 반대쪽은 파생시킨다**(목록을 두 번 적으면 한쪽만 고친다)

## 검증 도구 (CDP 실측)
`node scripts/measure.mjs --help`. 반투명·그라데이션 위 글자 대비는 **계산이 아니라 합성 픽셀**로만 판정한다 — 스크립트가 헤드리스 크롬을 몰아 로그인까지 진행하고, 캡처한 PNG를 페이지 안 canvas로 되돌려 잰다. **의존성 0**(Node 내장 `WebSocket`+`fetch`. `ws`·puppeteer 설치 금지). ⚠️ **바탕화면 아이콘은 `--dblclick`이라야 열린다**(`--click`은 `el.click()`이라 선택만 된다). 셀렉터는 텍스트로 못 고르므로 `--contrast .desktop-icon`으로 순서를 먼저 확인하고 `:nth-child(n)`을 쓴다.
⚠️ **실측은 새로 만든 화면에만 쓴다.** 기존 화면 수정·수치 조정은 테스트+빌드로 끝낸다(CLAUDE.md 검증 규칙).
